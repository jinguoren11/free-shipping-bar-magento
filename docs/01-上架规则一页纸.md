# Adobe Commerce Marketplace 免费插件上架规则（一页纸）

> 来源：Adobe 官方开发者文档（developer.adobe.com/commerce/marketplace/guides/sellers/ 下的
> technical-review-guidelines、submit-for-technical-review、profile-information、sales、
> marketing-review-guidelines、submit-for-marketing-review、extension-quality-program）。
> 2026-11-16 逐页读过，下面都是页面原文意思，不是凭记忆。

## 一、结论（老任最关心的）

1. **免费插件和收费插件走同一套审核**（技术审核 + 营销审核），没有"快速通道"。价格那一栏保持默认 0 就是免费。
2. **上架本身不收费**。Adobe 只对卖出去的东西抽 15%，免费插件没有任何费用。
3. **开发者账号要填 PayPal 邮箱——免费也必须填**（官方原话："You must enter a valid PayPal email, even if your listings are available for free"）。
4. **税表（W-9/W-8 之类）**：官方页面写"Marketplace 政策要求所有提供者提交业务信息"，并在个人资料里提供税表下载。
   但"拿不到钱就不处理税"这条明确是针对**收款（payout）**写的，而且收款还要求插件定价 ≥ 25 美元。
   **我们的插件免费，永远不会有收款**，所以税表大概率用不上；但官方没有明确写"免费免填"，最稳妥是等老任账号里看到有没有强制弹出税表，没有就先不填。
5. **欧盟"商家(trader)信息"要填**：想让欧盟用户看到插件，要填商家名称、商家邮箱、商家地址（DUNS 号可选），
   **这些会公开显示在欧盟用户看到的插件页面上**。→ 请老任决定用哪个邮箱/地址（建议用公司地址或专用邮箱，不要用家庭住址）。

## 二、开发者账号需要的资料

- Adobe ID（登录用）、Mage ID、屏幕名(Screen Name)、**Vendor Name（供应商名，一旦定了就是代码包名前缀，要慎重）**
- 至少 1 个地址（最多 3 个）、电话
- PayPal 邮箱（必填，免费也要）
- 公司：名称、联系人、支持邮箱、公司网址、公司简介（≤1500 字）、隐私政策网址（可选）
- 欧盟 trader：名称/邮箱/地址（公开显示）

## 三、技术审核（自动 + 人工）怎么过

| 项目 | 要求 |
|---|---|
| 包格式 | zip，**≤ 30MB**，根目录有 composer.json |
| composer.json 必须有 | `name`、`type`（插件写 `magento2-module`）、`version` |
| composer.json 不能有 | `extra.map`、`extra.magento-root-dir`；不能依赖 magento/magento2-base 等核心包；Magento 包版本不能写 `*`；不能用 inline alias；不能限制 PHP 版本范围 |
| 模块文件 | 必须有 `etc/module.xml`、`registration.php`；composer 的 `autoload.files` 含 registration.php，`autoload.psr-4` 至少一个命名空间 |
| 代码里 | **不能留 FIXME / TODO 注释**（审核会扫） |
| 安全 | 病毒/恶意代码扫描；抄袭检测（代码和营销文字都查） |
| 代码风格 | Marketplace 自定义 CodeSniffer（Magento2 编码标准）。不通过会给报告 |
| 安装测试 | 开 Varnish 缓存、每个支持的 PHP 版本、切到 production 模式安装；**缓存页要照常被 Varnish 直接返回** → 我们用"前端实时取数"的做法，不会破坏缓存 |
| 官方功能测试 | MFTF 跑一批 Magento 自带测试（游客下单、多地址结账、加心愿单、后台开发票等），插件不能把它们搞坏 |
| 人工 QA | composer 能装；`deploy:mode:set production` 编译无错；文档里写的功能都有、有的功能文档都写；无崩溃；填错数据不卡死 |
| 许可证 | 必须选一个：MIT / OSL-3.0 / Apache-2.0 等（或自定义）。**我们选 MIT** |
| 文档 | 至少 1 份 **PDF（<5MB）**：用户手册（必需）；安装指南/参考手册可选。**至少一份英文**。要覆盖全部功能。**不能引导用户去 Marketplace 以外的网站购买东西** |
| 发布说明 | Release Notes，≤10,000 字符，可用简单 HTML |

## 四、营销审核（上架页面）

- **标题**：≤5 个英文单词；每个词首字母大写；不能含 Magento / Adobe / M2 / Extension / Module / Plugin、版本号、开发者名。
  → 建议标题：**Free Shipping Progress Bar**（4 个词）
- **图标**：能体现功能；不能用 Adobe/Magento 的 logo；不能用开发者 logo 代替；不放口号。
- **图片**：缩略图 1 张 + 至少 2 张截图（最多 15 张），JPG/PNG，每张 ≤5MB；截图要裁掉网址栏和多余空白。
- **长描述**：≤25,989 字符，无错别字语法错误；选 1 个主分类 + 最多 3 个子分类；描述要准确（版本兼容、分类）。
- **价格**：免费 = 0。
- **稳定性**：Beta 或 Stable，选对应的。
- **勾选项**：有没有 setup scripts、Web API、响应式等。
- **品牌**：不得侵犯 Magento/Adobe 商标。

## 五、⚠️ 需要老任拍板的风险点：GetDropFlow 引流链接

官方原话：**"The promotion of additional services or other extensions from your extension profile page is not allowed."**
文档里也不能引导到别的网站购买。所以：

- ✅ **安全位置**：GitHub 仓库 README（完全自由）；开发者资料里的 **Company URL**（官方允许，所有插件页都会带这个链接）；PDF 手册末尾"作者"一行**只放网址和一句话介绍**，不放"购买/订阅/注册"字样。
- ⚠️ **有风险**：插件列表页的描述里放推广语；后台设置页里放"去 GetDropFlow 购买"之类的字样。
- 我的做法：插件本身**不在买家前台显示任何广告**（也不会被审核拒）；后台设置页底部只放一行很轻的"作者：GetDropFlow（getdropflow.com）"，且**可见但不带购买诱导**；上架页描述不放推广，推广靠 Company URL + GitHub README。
  如果老任想更激进，我可以做，但会提高被拒概率。

## 六、需要老任批准/提供的事（清单）

1. **Vendor Name**（供应商名）：决定代码包名前缀。目前代码暂用 `GetDropFlow\FreeShippingBar`，如账号里的 Vendor Name 不同，我一键改名。
2. 欧盟 trader 公开信息用哪个名称/邮箱/地址。
3. 是否接受第五节的引流方式。
4. 账号里 PayPal 邮箱怎么填（这是账号资料，我不碰）。
